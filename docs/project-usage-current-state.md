# 项目使用逻辑说明

更新时间：2026-05-17

这份说明按当前实现整理。项目现在的主线已经从“手动上传简历生成方案”，调整为“资料入库 -> 知识资产检索 -> 方案 Agent -> 客户案卷 -> AI 执行交付”。

## 1. 当前产品主线

当前推荐使用链路是：

客户问题 -> 资料入库 -> 自动切片/标签/评分 -> 知识资产库 -> 方案 Agent 检索证据 -> 生成方案草案和动态 AI 执行员工 -> 生成客户案卷 -> 任务板执行 -> 方案文档导出

核心变化：

- 手动上传入口已经改成通用“资料入库”，不再要求按简历模式上传。
- `/resumes/upload` 会跳转到 `/knowledge-assets/intake`。
- 主导航保留“方案 Agent”，旧的“方案生成”和“AI 产品经理”入口不再作为主入口展示。
- `/industry-agent` 和 `/ai-product-manager` 历史链接会跳转到 `/ai-employees`，避免继续进入旧的分散生成链路。
- 邮箱同步仍然保留，适合自动同步 BOSS 邮箱里的简历/能力样本附件。

## 2. 数据入口

### 2.1 资料入库

页面：`/knowledge-assets/intake`

用途：放外部报告、官方资料、竞品资料、客户模板、内部纪要、方法论、案例材料。

支持：

- PDF
- DOCX
- TXT
- Markdown
- 直接粘贴正文

链路：

1. 用户上传资料文件，或粘贴正文。
2. 前端调用 `POST /api/knowledge-assets/upload` 或 `POST /api/knowledge-assets/intake`。
3. 后端保存文件到 `uploads/knowledge`。
4. 后端抽取文本。
5. 长文本会按片段切分成多条 `KnowledgeAsset`。
6. 系统生成摘要、标签、证据评分、可信度和适用边界。
7. 资产进入“待复核”状态。
8. 方案 Agent 从这里检索证据。

建议你以后从外面找到有效报告或资料时，优先走这个入口。

### 2.2 知识资产库

页面：`/knowledge-assets`

用途：查看和筛选已经入库的证据资产。

可以按下面维度管理：

- 来源类型
- 行业标签
- 业务主题
- 证据类型
- 证据强度
- 数据验证评分
- 商业价值评分
- 人工复核状态

这些资产会被方案 Agent 引用。每条资产会保留来源、摘要、原文片段、能证明什么、不能证明什么、适用条件和迁移风险。

### 2.3 邮箱样本

页面：`/resumes`

用途：保留从邮箱同步的人才简历和能力样本。

当前逻辑：

1. 系统读取配置好的 IMAP 邮箱。
2. 识别 BOSS 相关邮件和附件。
3. 附件进入原 `Resume` 解析队列。
4. 解析出的项目经历、工作经历会同步成 `KnowledgeAsset`。

这个入口不再作为通用资料上传入口。手动上传外部报告、客户文档、政策资料时，走“资料入库”。

## 3. 方案 Agent 生成链路

页面：`/ai-employees`

当前它是统一生成入口，页面名称是“方案 Agent”。

链路：

1. 用户输入客户需求、公司资料、项目资料、约束条件。
2. 前端调用 `POST /api/solution-agent/generate`。
3. 后端把需求、公司背景、项目资料和约束合成检索 query。
4. 后端从 `KnowledgeAsset` 检索相关证据。
5. 系统评估证据覆盖率。
6. 如果证据不足，系统不会直接强行调用模型生成完整方案，而是返回缺口、追问和下一步补资料动作。
7. 如果证据达到可生成草案的程度，系统把知识资产证据传给大模型。
8. 模型输出方案标题、摘要、方案方向、能力要求、风险、追问问题和动态 AI 执行员工。
9. 页面展示 Agent 运行链路、证据资产、证据覆盖、缺口、方案草案和人工决策点。
10. 用户点击“生成客户案卷”，进入客户交付流程。

这个链路比旧版本更接近 Agent 逻辑，因为它不是只换一个模型入口，而是包含：

- 需求理解
- 证据检索
- 覆盖率评估
- 证据不足时阻断生成
- 模型生成或规则兜底
- 动态 AI 执行员工拆解
- 人工决策点输出
- 可追溯运行链路

## 4. 客户案卷与交付

页面：`/customer-projects`

链路：

1. 从方案 Agent 生成客户案卷。
2. 系统创建 `CustomerProject`。
3. 系统创建方案文档 `SolutionDocument`。
4. 系统生成任务板 `ProjectTask`。
5. 用户在客户案卷中生成诊断、生成任务板、执行任务。
6. 每个任务可以生成 AI 执行草稿。
7. 人工验收后，输出会写入方案文档。
8. 方案文档可以编辑和导出 Markdown。

需要注意：客户案卷里的任务执行目前仍然偏模板化，还没有完全做到每个任务都重新带着证据上下文调用 Agent 深度执行。这是下一阶段要继续增强的部分。

## 6. 现在建议怎么用

### 情况 A：你有外部报告、官方资料、竞品资料、客户文档

1. 进入“资料入库”。
2. 上传 PDF/DOCX/TXT/Markdown，或粘贴正文。
3. 填来源类型、来源名称、保密级别和标签。
4. 保存后进入“知识资产库”。
5. 打开“方案 Agent”输入客户需求。
6. 查看系统检索到哪些证据、证据覆盖率是否足够。
7. 如果缺资料，按系统追问补充资料。
8. 证据足够后生成方案。
9. 生成客户案卷。

### 情况 B：你通过邮箱自动同步简历/能力样本

1. 在系统设置里配置邮箱。
2. 邮箱样本同步进入 `/resumes`。
3. 系统解析样本中的工作经历和项目经历。
4. 这些经历会同步为知识资产。
5. 后续由方案 Agent 检索引用。

### 情况 C：你要做客户交付

1. 先把客户材料、外部报告、历史案例放进资料入库。
2. 用方案 Agent 生成第一版方案。
3. 检查引用证据和人工决策点。
4. 点击“生成客户案卷”。
5. 在客户案卷里生成诊断和任务板。
6. 让 AI 执行员工生成草稿。
7. 人工验收后写入方案文档。
8. 导出交付文档。

## 7. 当前还没有完全解决的点

- 检索还是关键词和标签匹配，没有向量检索。
- 资料切片是按文本长度，不是按真实章节目录。
- 暂不支持 URL 自动抓取网页。
- 客户案卷内的任务执行还不是完整多轮 Agent。
- 旧招聘模型仍然存在，`Resume` 还没有重命名为更贴近当前产品的能力样本模型。
- README 仍有旧招聘系统描述，后续需要重写成方案 Agent 产品说明。

## 8. 一句话结论

现在系统已经不需要把外部资料当简历上传。通用资料应该进入“资料入库”，系统会抽文本、切片、打标签并进入知识资产库；方案 Agent 会基于这些知识资产检索证据，再决定是否生成方案、生成什么方案、还缺什么资料，以及需要哪些 AI 执行员工和人工审核点。
